# 任务提交额度 - 前端对接说明

## 一、接口变更概览

| 接口 | 说明 |
|-----|------|
| `POST /v1/task/submit` | 提交任务，成功时返回 `quota` 额度信息；超限时返回 1010 错误及 `data` 中的额度详情 |
| `POST /v1/task/clarify` | 追问（生成追问问题），需登录且校验当日额度，超限时返回 1010 |
| `GET /v1/task/submit-quota` | 查询当前用户剩余额度（提交前可调用，用于展示「今日还可提交 X 次」） |

---

## 二、提交成功响应 `POST /v1/task/submit`

```json
{
  "meta": {
    "statusCode": 0,
    "statusMsg": "success",
    "traceId": "xxx"
  },
  "data": {
    "taskId": 123,
    "quota": {
      "dailyLimit": 3,
      "usedToday": 2,
      "remainingQuota": 1,
      "quotaResetAt": "2025-02-15 00:00:00"
    }
  }
}
```

- `quota` 为 `null`：管理员或未启用限额，可不展示额度
- `quota` 有值：普通用户，可展示「今日已用 X/3 次，剩余 Y 次，将于 Z 重置」

---

## 三、额度超限响应 `POST /v1/task/submit`（超出每日上限）

**HTTP 400**，`meta.statusCode === 1010`

```json
{
  "meta": {
    "statusCode": 1010,
    "statusMsg": "Daily task submission limit reached (3 times). Please try again tomorrow.",
    "traceId": "xxx"
  },
  "data": {
    "dailyLimit": 3,
    "usedToday": 3,
    "remainingQuota": 0,
    "quotaResetAt": "2025-02-15 00:00:00"
  }
}
```

**前端处理建议：**
- 判断 `meta.statusCode === 1010` 时，弹窗提示（可用 `statusMsg` 或自行组合）："Daily limit reached. Resets at {quotaResetAt}"
- 可使用 `data.dailyLimit`、`data.usedToday`、`data.quotaResetAt` 组合展示

---

## 四、查询额度 `GET /v1/task/submit-quota`

```json
{
  "meta": {
    "statusCode": 0,
    "statusMsg": "success",
    "traceId": "xxx"
  },
  "data": {
    "dailyLimit": 3,
    "usedToday": 1,
    "remainingQuota": 2,
    "quotaResetAt": "2025-02-15 00:00:00"
  }
}
```

- `data` 为 `null`：管理员或未启用限额，可不展示额度相关 UI
- `data` 有值：可展示「今日还可提交 X 次」，或在提交按钮旁显示剩余次数

---

## 五、错误码说明

| 错误码 | 含义（statusMsg 为英文） |
|-------|------|
| 1010 | Daily task submission limit reached (N times). Please try again tomorrow. |
| 9999 | Internal server error / System error |

---

## 六、配置说明（后端）

- 配置文件：`application.yml` 中的 `task.submit.daily-limit-per-user`
- 环境变量：`TASK_DAILY_LIMIT_PER_USER`（可覆盖配置）
- 默认值：3（每日最多 3 次）
- 设为 0 或负数：不限制
