# SpringBoot 后端启动测试指南

## 🚀 启动步骤

### 1. 前置准备

#### 1.1 确保 MySQL 数据库已启动

```bash
# 检查 MySQL 是否运行
mysql -u root -p -e "SHOW DATABASES;"
```

#### 1.2 创建数据库（如果不存在）

```bash
mysql -u root -p << EOF
CREATE DATABASE IF NOT EXISTS studyagent CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
USE studyagent;
EOF
```

#### 1.3 执行初始化 SQL

```bash
# 使用项目中的 init.sql
mysql -u root -p studyagent < ../docker/init.sql
```

### 2. 配置环境变量（可选）

创建 `.env` 文件或设置环境变量：

```bash
export DB_USERNAME=root
export DB_PASSWORD=your_password
export CLERK_SECRET_KEY=sk_test_xxx
export STRIPE_SECRET_KEY=sk_test_xxx
```

### 3. 构建项目

```bash
cd studyagent-backend
mvn clean install -DskipTests
```

### 4. 启动应用

```bash
cd agent-start
mvn spring-boot:run
```

或者：

```bash
java -jar agent-start/target/agent-start-1.0.0-SNAPSHOT.jar
```

## ✅ 测试接口

### 1. 健康检查（最简单，不需要数据库）

```bash
curl http://localhost:8080/health
```

**预期响应**:
```json
{
  "meta": {
    "statusCode": 0,
    "statusMsg": "success"
  },
  "data": {

    "app_name": "StudyAgent Backend",

    "database": "connected"
  }
```

### 2. Swagger UI（查看所有接口）

访问浏览器: http://localhost:8080/swagger-ui.html

```bash
  -H "Content-Type: application/json" \
```

## ⚠️ 常见启动问题

### 问题1: 数据库连接失败

**错误信息**:
```
Communications link failure
或
Access denied for user 'root'@'localhost'
```

**解决方案**:
1. 检查 MySQL 服务是否启动: `mysql -u root -p`
2. 检查 `application.yml` 中的数据库配置
3. 确认数据库 `studyagent` 已创建
4. 确认用户名密码正确

### 问题2: 端口被占用

**错误信息**:
```
Port 8080 is already in use
```

**解决方案**:
1. 修改 `application.yml` 中的 `server.port`
2. 或停止占用 8080 端口的进程

### 问题3: Bean 注入失败

**错误信息**:
```
No bean named 'xxxMapper' available
```

**解决方案**:
1. 确认 `MyBatisConfig` 的 `@MapperScan` 配置正确
2. 确认 Mapper 接口在正确的包路径下
3. 重新构建项目: `mvn clean install`

### 问题4: Clerk Token 验证失败

**错误信息**:
```
Invalid token
```

**解决方案**:
1. 配置正确的 Clerk Secret Key
2. 或暂时修改 `AuthInterceptor`，允许未认证访问（仅用于测试）

### 问题5: Python 后端调用失败

**错误信息**:
```
Connection refused: http://localhost:8000
```

**解决方案**:
1. 确保 Python 后端运行在 http://localhost:8000
2. 或暂时注释掉 `TaskApplicationService` 中的 Python 后端调用

## 🎯 最小化测试

如果只想测试项目能否启动，可以：

1. **不配置数据库** - 只测试健康检查接口
2. **不配置 Clerk** - 只测试不需要认证的接口
3. **不配置 Stripe** - 跳过支付相关接口
4. **不启动 Python 后端** - 跳过任务执行调用

## ✅ 可以正常调用的接口（最小配置）

即使不配置外部服务，以下接口也应该可以调用：

1. ✅ GET `/health` - 健康检查
2. ✅ GET `/swagger-ui.html` - API 文档
3. ⚠️ POST `/v1/task/list` - 需要数据库（但可以返回空列表）
4. ⚠️ POST `/v1/task/detail` - 需要数据库（但可以返回错误）

## 🚨 必须配置才能使用的接口

以下接口需要相应的配置：

- **需要数据库**: 所有涉及数据查询/保存的接口
- **需要 Clerk**: `/v1/auth/me`, `/v1/task/submit`
- **需要 Stripe**: `/v1/payment/*`, `/v1/webhook/stripe`
- **需要 Python 后端**: `/v1/task/submit`（执行任务时）
