# 数据机器人推送说明（data_bot 相关实现）

本文档梳理当前后端中与「钉钉 / Notify 数据机器人」相关的实现：**触发方式**、**Notify 通道参数**、**推送正文大致结构**、**配置与代码位置**。详细 HTTP 协议见 [NotifyAPI接口文档.md](./NotifyAPI接口文档.md)。

---

## 1. 总体架构

| 组件 | 作用 |
|------|------|
| `RobotNotifyService` | 同步调用内部 `NotifyApplicationService`；按 **`RobotNotifyRouteKind`** 解析钉钉 **`target`**（路由到不同群机器人）。 |
| `RobotNotifyRouteKind` | 内部推送类别：`ASSIGNMENT`（作业侧 Stripe 播报）、`FEEDBACK`（用户反馈）、`REPORT`（数据报表）；未分类可走 `DEFAULT`（`notify.default-target`）。 |
| `RobotNotifyAsyncService` | 业务事件（支付、用户反馈）后 **异步** 组装 Markdown，再调用 `RobotNotifyService`。线程池：`robotNotifyExecutor`（见 `AsyncConfig`）。 |
| `DataReportService` | 按日/周从 **MySQL** 聚合指标，组装 Markdown，**异步** 调用 `RobotNotifyService`（路由类别 `REPORT`）。 |
| `DataReportScheduler` | 北京时间定时触发日报、周报。 |
| `DataReportTriggerController` | 手动触发日报/周报（联调、补发）。 |

**共性：**

- `sourceService` 固定为 `springboot_backend`（与 Notify 文档一致）。
- `contentType` 一般为 `markdown`；正文长度受 Notify 侧限制（当前实现中标题 ≤80 字、正文 ≤2000 字会截断）。
- 实际是否发出取决于 `notify.enabled=true` 且 `notify.api-token` 与请求头 `X-Notify-Token` 一致（内部调用时由 `RobotNotifyService` 注入配置 token）。

## 1.1 钉钉多机器人（`target`）与三类推送

内部推送不再默认「全部进同一个群」：每条消息会带 Notify必填字段 **`target`**，其值为 **钉钉配置文件** `dingtalk-webhook-config.yml` 里 **`targets.<key>`** 的名称（小写）。

| 业务类别 | `RobotNotifyRouteKind` | Spring配置项（值为 YAML 里的 target key） | 覆盖的 `scene` / 场景 |
|----------|------------------------|---------------------------------------------|------------------------|
| 作业侧商业播报（Stripe） | `ASSIGNMENT` | `notify.robot-target.assignment`（环境变量 `NOTIFY_ROBOT_TARGET_ASSIGNMENT`） | `notify.payment.success`、`notify.payment.failed`、`notify.checkout.expired` |
| 用户反馈 | `FEEDBACK` | `notify.robot-target.feedback`（`NOTIFY_ROBOT_TARGET_FEEDBACK`） | `notify.feedback.submitted` |
| 数据日报 / 周报 | `REPORT` | `notify.robot-target.report`（`NOTIFY_ROBOT_TARGET_REPORT`） | `notify.report.daily`、`notify.report.weekly` |

**默认行为：** 上述三项在 `application.yml` 中 **默认均为 `default`**，与历史「单群」一致——即三类消息都走 **`targets.default`** 这一套 webhook。若要 **三个群三套机器人**，请在：

1. **`config/dingtalk-webhook-config.yml`**（路径由 `notify.dingtalk.config-file` / `NOTIFY_DINGTALK_CONFIG_FILE` 指定）中增加 **`assignment` / `feedback` / `report`** 等节点（示例见仓库 **`config/dingtalk-webhook-config.example.yml`**）；
2. 在 **`application.yml` 或环境变量** 中把 `notify.robot-target.assignment|feedback|report` 设为与 YAML 一致的 key。

**约束：** `DingTalkWebhookConfigLoader` 要求配置文件中 **必须存在 `targets.default`**；某线路由到的 key 若不存在，Notify 会返回 **4004（target invalid）**，该次推送失败。

**与对外 Notify HTTP API 的区别：** `POST /api/v1/notify/events` 由调用方在 JSON 里自行传 `target`；本文档所述三类为 **后端内部** 固定映射，不经过该接口的 body拼装。

## 2. 业务事件类推送（付费播报 / 用户反馈群）

> **钉钉路由：** 2.1–2.3 使用 **`ASSIGNMENT`** → `notify.robot-target.assignment`；2.4 使用 **`FEEDBACK`** → `notify.robot-target.feedback`。

### 2.1 付款成功

| 项目 | 说明 |
|------|------|
| **触发时机** | Stripe Webhook `checkout.session.completed`，且 `QuotaRechargeService.processRecharge` 返回 **成功**（首次到账，非幂等跳过）。 |
| **入口代码** | `WebhookController.handleCheckoutSessionCompleted` → `RobotNotifyAsyncService.notifyPaymentSucceeded` |
| **Notify `scene`** | `notify.payment.success` |
| **幂等 `eventId`** | Stripe 事件 ID（`stripeEventId`） |

**标题示例：** `[付费播报] Assignment · 付款成功 · 首购`（功能名随 `feature_code`：Assignment / AI Detection / Humanizer；末段为首购/复购）

**正文主要字段（Markdown列表）：**

- Stripe 事件类型、`功能·状态·首复购`、套餐（额度/次数 + 金额 + package编码）
- 购买来源：当前固定文案「未追踪」（需 Checkout `metadata` 扩展 `purchase_source` 才可细化）
- UID、邮箱（Stripe 会话）、国家/首访（当前「未入库」）
- 上次任务相关摘要（按功能：Assignment 最近任务创建距今天数 / Detection·Humanize 最近任务）
- 复购用户额外：复购间隔（天）、本功能累计付费（成功订单金额汇总）
- 各功能月均付费（注册满 30 天按公式估算；不足30 天显示「不足一月」）
- 上次任务链接（`app.public-site-url` + `/editor/{Sqids}` 或 Humanizer 页说明）
- UTC时间、Stripe session / payment_intent / event id

**metadata 示例键：** `kind=payment_success`、`stripe_event_id`、`clerk_user_id`、`feature_code`、`stripe_session_id` 等。

---

### 2.2 付款失败

| 项目 | 说明 |
|------|------|
| **触发时机** | `charge.failed` 或 `payment_intent.payment_failed`，且 `processPaymentFailed` **首次落库成功**（幂等跳过则不再推送）。 |
| **入口代码** | `WebhookController.handleChargeFailed` / `handlePaymentIntentFailed` → `RobotNotifyAsyncService.notifyPaymentFailed` |
| **Notify `scene`** | `notify.payment.failed` |
| **幂等 `eventId`** | `payment_failed_{paymentIntentId}`（避免同一失败被两种 Stripe 事件各推一次） |

**标题示例：** `[付费播报] Assignment · 付款失败 · 首购`（首复购按历史成功订单推断）

**正文要点：** Stripe 事件类型、功能、套餐、UID、失败原因、PaymentIntent、UTC 时间（邮箱行当前为占位「—」）。

**metadata：** `kind=payment_failed`、`payment_intent_id` 等。

---

### 2.3 退出付款（Checkout 过期）

| 项目 | 说明 |
|------|------|
| **触发时机** | Stripe `checkout.session.expired`（需在 Stripe 控制台为该事件配置 Webhook）。 |
| **入口代码** | `WebhookController.handleCheckoutSessionExpired` → `RobotNotifyAsyncService.notifyCheckoutExpired` |
| **Notify `scene`** | `notify.checkout.expired` |
| **幂等 `eventId`** | Stripe 事件 ID |

**标题示例：** `[付费播报] Assignment · 退出付款 · 首购`

**正文要点：** 事件类型、功能、套餐、UID、来源说明（未追踪 metadata）、Session id、UTC 时间。

---

### 2.4 用户反馈提交

| 项目 | 说明 |
|------|------|
| **触发时机** | `POST /v1/feedback/submissions` 事务提交成功后，在 `FeedbackController` 中调用异步推送（避免与事务未提交竞态）。 |
| **入口代码** | `FeedbackController.submitFeedback` → `RobotNotifyAsyncService.notifyFeedbackSubmitted` |
| **Notify `scene`** | `notify.feedback.submitted` |
| **幂等 `eventId`** | `feedback_{submissionId}` |

**标题示例：** `[Assignment 用户反馈] fsub_xxx`（或 AI Detection / Humanizer，由会话 `subject_type` + Humanizer 任务类型决定）

**正文要点（通用）：**

- 功能、评分（1–5 星）或 好评/差评（thumb）、标签 JSON、自定义评价、联系方式
- UID；邮箱/国家/首访：当前「未入库」类说明
- **反馈时机**：`trigger_code` 映射中文（如点击 Download、从编辑页返回、Detection/Humanizer 流程结束等）

**Assignment（`subject_type=task`）额外：**用户类型（新/老用户）、任务编辑器链接、上传文件分布、Query截断、Subject/Academic/Citation/页数、任务执行时长、追问 Q&A 片段（来自 `requirement_json`）。`subject_id` 支持 **数字 ID 与 Sqids 短码**。

**Humanizer 任务（`subject_type=humanizer_task`）额外：** 任务页说明链接、Detection或 Humanize 耗时/字数、AI 概率（Detect）、入口（编辑器内/外）、用户类型。

**metadata：** `kind=feedback`、`submission_id`、`prompt_session_id`、`clerk_user_id`。

## 3. 定时数据报表类推送（数据日报 / 周报）

> **钉钉路由：** 本章全部使用 **`REPORT`** → `notify.robot-target.report`（日报与周报同一 target，便于进「数据群」）。

### 3.1 日报

| 项目 | 说明 |
|------|------|
| **触发时机** | 默认每天 **北京时间 12:00**，统计 **昨天** `00:00–24:00`（BJT）。 |
| **调度** | `DataReportScheduler.runDaily`（cron：`report.daily-cron`，默认 `0 0 12 * * ?`，`zone=Asia/Shanghai`） |
| **手动** | `POST /v1/internal/reports/daily`，Header：`X-Report-Token`；可选 `date=yyyy-MM-dd`（缺省为昨天 BJT） |
| **Notify `scene`** | `notify.report.daily` |
| **幂等 `eventId`** | `daily_report_{yyyy-MM-dd}` |

**标题：** `DataReportService.pushDailyReportAsync` 中拼接为：前缀图表 emoji（与代码一致）+ `report.title-prefix` + `日报 · ` + 统计日 `yyyy-MM-dd`。

**正文结构（节选）：**

- **访问（DB 可算）：** 新用户注册数 + 环比；DAU / 首访 Top5 标为「暂无」
- **任务：** 创建数、成功数、失败数、成功率、平均执行时长 + 环比
- **转化（部分）：** 注册→创建（期内新注册用户中同期有非草稿任务的人数占比）、创建→完成；完成→编辑 / 编辑→消费标「暂无」
- **反馈：** Assignment / Detection / Humanizer 条数及环比说明、Assignment 均分、Detection/Humanizer 好评率 + 环比
- **对比基准：** 7 天前同一自然日

**口径说明：** 任务创建 = `created_at` 在窗口内且 **非草稿**；成功/失败 = `finish_time` 在窗口内且 `status` 为已完成/失败；详见 `DataReportService` 注释。

---

### 3.2 周报

| 项目 | 说明 |
|------|------|
| **触发时机** | 默认每周日 **北京时间 12:00**，统计区间 **`[weekEndExclusive-7天, weekEndExclusive)`**（右端点为当周周日 0点，不含）。 |
| **调度** | `DataReportScheduler.runWeekly`（`report.weekly-cron`，默认 `0 0 12 ? * SUN`） |
| **手动** | `POST /v1/internal/reports/weekly`，`X-Report-Token`；可选 `weekEndExclusive=yyyy-MM-dd`（缺省为当前 BJT 下「最近一个星期日」） |
| **Notify `scene`** | `notify.report.weekly` |
| **幂等 `eventId`** | `weekly_report_{weekEndExclusive}` |

**标题：** `DataReportService.pushWeeklyReportAsync` 中拼接为：前缀图表 emoji（与代码一致）+ `report.title-prefix` + `周报 · ` + 周起始日 `MM-dd` + ` - ` + 周最后一天 `MM-dd`（后者为 `weekEndExclusive` 的前一天）。

**正文：** 在日报基础上增加 **整周付费**：总收入（`recharge_orders` 成功、`paid_at` 窗口）、付费人数、新付费/复购占比、三功能订单数+SKU 分布、收入占比；若存在非 USD 订单会提示金额未做汇率换算。

**对比基准：** 上一完整自然周（再往前 7 天）。

## 4. 配置一览（application.yml / 环境变量）

| 配置项 | 含义 |
|--------|------|
| `notify.enabled` | 是否启用 Notify（关闭则所有推送在 `RobotNotifyService` 内直接跳过）。 |
| `notify.api-token` | Notify 鉴权；内部调用与 `POST /api/v1/notify/events` 的 `X-Notify-Token` 一致。 |
| `notify.default-target` | 未使用分类路由或 `RobotNotifyRouteKind.DEFAULT` 时的钉钉 target key（默认 `default`）。 |
| `notify.robot-target.assignment` | Stripe 付费类内部推送的 target key（默认 `default`）。 |
| `notify.robot-target.feedback` | 用户反馈内部推送的 target key（默认 `default`）。 |
| `notify.robot-target.report` | 日报/周报内部推送的 target key（默认 `default`）。 |
| `notify.dingtalk.config-file` | 钉钉 `targets` YAML 的绝对路径（`NOTIFY_DINGTALK_CONFIG_FILE`）；启用 Notify 时必填且可读。 |
| `notify.default-env` | `local` / `test` / `online`。 |
| `app.public-site-url` | 付费成功/反馈中的前端链接前缀。 |
| `report.scheduling-enabled` | 是否启用日报/周报 **定时** 调度。 |
| `report.manual-trigger-token` | 手动报表接口 `X-Report-Token`；**与 Notify token 独立**。 |
| `report.title-prefix` | 报表标题前缀（默认 `Verla 数据`）。 |
| `report.daily-cron` / `report.weekly-cron` | 覆盖默认 cron。 |

**多群示例（环境变量）：** 在钉钉 YAML 中已配置 `targets.assignment`、`targets.feedback`、`targets.report` 时，可设置 `NOTIFY_ROBOT_TARGET_ASSIGNMENT=assignment`、`NOTIFY_ROBOT_TARGET_FEEDBACK=feedback`、`NOTIFY_ROBOT_TARGET_REPORT=report`。

**安全说明：** 仓库内可为本地提供占位默认 token；钉钉 webhook 文件见 **`config/dingtalk-webhook-config.example.yml`**，真实文件 **`config/dingtalk-webhook-config.yml`** 已 `.gitignore`。**测试/生产务必用环境变量覆盖 token与密钥路径**，勿将真实密钥提交到 Git。

## 5. HTTP 与鉴权（与业务接口关系）

| 路径 | 鉴权 |
|------|------|
| `/v1/internal/reports/**` | **排除** Clerk `Authorization`；使用 `X-Report-Token` = `report.manual-trigger-token`。 |
| `/v1/feedback/submissions` | 需正常 Clerk 登录；推送在成功后异步执行。 |
| `/v1/webhook/stripe` | Stripe 签名 `stripe-signature`。 |

## 7. 已知能力与文档 PRD 的差异（便于排期）

- **付费：** 购买来源、国家、首访、用户本地时区等依赖 metadata 或用户表扩展；失败推送中 Stripe 邮箱可后续从 PaymentIntent 补全。
- **反馈：** 编辑器停留时长、追问补充文件、support 邮件通道等未接。
- **日报/周报：** DAU、新用户来源 Top5、完成→编辑、编辑→消费依赖埋点或数仓；周报多币种仅提示不换算。
