# 日志系统使用说明

## 概述

本项目实现了一套统一的日志打印方案，主要包括：

1. **Controller 层 API 日志**：自动记录 HTTP 请求的入参、出参、耗时
2. **外部调用日志**：自动记录调用外部服务（Python 后端、Clerk API 等）的入参、出参、耗时
3. **链路追踪**：通过 TraceId 实现请求链路追踪，方便问题排查


## 使用方式

### 1. Controller 层 API 日志

#### 自动日志（无需注解）

所有 `com.studyagent.api.controller` 包下的 Controller 方法会自动记录日志：

```java
@RestController
@RequestMapping("/v1/task")
public class TaskController {
    
    @PostMapping("/submit")
    public Result<SubmitTaskResponse> submitTask(@RequestBody SubmitTaskRequest request) {
        // 自动记录入参、出参、耗时
        return Result.success(response);
    }
}
```

#### 使用 @ApiLog 注解自定义

```java
@ApiLog(
    description = "提交任务",           // 接口描述
    logRequest = true,                  // 是否打印请求入参
    logResponse = true,                 // 是否打印响应出参
    logHeaders = false,                 // 是否打印请求头
    sensitiveFields = {"password", "token"}, // 需要脱敏的字段
    maxLength = 4096,                   // 最大日志长度
    slowThreshold = 3000                // 慢请求阈值（毫秒）
)
@PostMapping("/submit")
public Result<SubmitTaskResponse> submitTask(@RequestBody SubmitTaskRequest request) {
    return Result.success(response);
}
```

#### 日志输出示例

```
2026-01-28 10:30:00.123 [http-nio-8080-exec-1] INFO  [a1b2c3d4e5f67890] [] ApiLogAspect - [a1b2c3d4e5f67890] [POST /v1/task/submit] [提交任务] >>> REQUEST | ip=192.168.1.1 | params={"request":{"taskTitle":"作业1"}}
2026-01-28 10:30:00.456 [http-nio-8080-exec-1] INFO  [a1b2c3d4e5f67890] [] ApiLogAspect - [a1b2c3d4e5f67890] [POST /v1/task/submit] [提交任务] <<< RESPONSE | cost=333ms | response={"meta":{"statusCode":0},"data":{"taskId":123}}
```

### 2. 外部调用日志

使用 `@ExternalLog` 注解标记调用外部服务的方法：

```java
@Component
public class PythonBackendClientImpl implements PythonBackendClient {
    
    @Override
    @ExternalLog(
        service = "Python后端",          // 外部服务名称
        api = "执行任务",                 // API 名称
        logRequest = true,               // 是否打印请求入参
        logResponse = true,              // 是否打印响应出参
        sensitiveFields = {"token"},     // 需要脱敏的字段
        maxLength = 4096,                // 最大日志长度
        slowThreshold = 5000,            // 慢请求阈值（毫秒）
        ignoreException = false          // 是否忽略异常日志
    )
    public void executeTask(TaskId taskId) {
        // 调用 Python 后端
    }
}
```

#### 日志输出示例

```
2026-01-28 10:30:00.200 [http-nio-8080-exec-1] INFO  [a1b2c3d4e5f67890] [] ExternalLogAspect - [a1b2c3d4e5f67890:12345678] [EXTERNAL] [Python后端] [执行任务] >>> CALL | params={"taskId":{"value":123}}
2026-01-28 10:30:01.500 [http-nio-8080-exec-1] INFO  [a1b2c3d4e5f67890] [] ExternalLogAspect - [a1b2c3d4e5f67890:12345678] [EXTERNAL] [Python后端] [执行任务] <<< RESULT | cost=1.30s | response=null
```

### 3. 链路追踪（TraceId）

#### 自动生成 TraceId

每个 HTTP 请求都会自动生成一个唯一的 TraceId，用于关联同一请求的所有日志。

#### 分布式追踪

支持通过请求头传递 TraceId，实现分布式链路追踪：

```bash
# 前端或其他服务调用时可以传入 TraceId
curl -H "X-Trace-Id: custom-trace-id-123" http://localhost:8080/v1/task/list
```

响应头中也会返回 TraceId：

```
X-Trace-Id: custom-trace-id-123
```

#### 在代码中获取 TraceId

```java
import com.studyagent.common.log.util.TraceIdUtil;

// 获取当前请求的 TraceId
String traceId = TraceIdUtil.getTraceId();

// 设置用户 ID（会自动添加到日志中）
TraceIdUtil.setUserId(clerkUserId);
```

### 4. 敏感字段脱敏

系统会自动对敏感字段进行脱敏处理，支持的字段包括：

- `password`, `pwd`
- `secret`, `secretKey`, `secret_key`
- `token`, `accessToken`, `access_token`
- `authorization`
- `apiKey`, `api_key`
- `privateKey`, `private_key`
- `credential`, `credentials`

脱敏后的输出：

```json
{"username":"admin","password":"******","token":"******"}
```

### 5. 日志格式说明

日志格式配置（application.yml）：

```yaml
logging:
  pattern:
    console: "%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level [%X{traceId:-}] [%X{userId:-}] %logger{36} - %msg%n"
    file: "%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level [%X{traceId:-}] [%X{userId:-}] %logger{36} - %msg%n"
```

格式说明：
- `%d{...}`: 时间戳（精确到毫秒）
- `[%thread]`: 线程名
- `%-5level`: 日志级别（左对齐，5字符宽度）
- `[%X{traceId:-}]`: TraceId（链路追踪）
- `[%X{userId:-}]`: 用户ID
- `%logger{36}`: 日志器名称（最多36字符）
- `%msg`: 日志消息
- `%n`: 换行符

## 日志级别说明

| 级别 | 场景 |
|------|------|
| INFO | 正常请求/响应 |
| WARN | 慢请求（超过阈值）、忽略的异常 |
| ERROR | 请求异常、外部调用失败 |

## 性能优化

1. **日志截断**：超过 `maxLength` 的日志会自动截断，避免大对象打印影响性能
2. **敏感字段懒加载**：只有需要打印日志时才进行脱敏处理
3. **MDC 清理**：请求结束后自动清理 MDC，避免内存泄漏

## TaskId 编解码（查日志用）

前后端对外暴露的 taskId 使用 Sqids 编码，数据库和日志中使用的是真实的自增 ID。
研发查日志时，若只有编码后的 taskId，可用以下方式获取真实 ID：

```bash
# 方式1：使用脚本（推荐）
pip install sqids
python scripts/decode_task_id.py Kx3nB

# 方式2：一行命令
python -c "from sqids import Sqids; s=Sqids(alphabet='FxnXM1kBN6cuhsAvjW3Co7l2RePyY8DwaU04Tzt9fHQrqSVKdpimLGIJOgb5ZE',min_length=5); print(s.decode('Kx3nB')[0])"
```

脚本路径：项目根目录 `scripts/decode_task_id.py`
