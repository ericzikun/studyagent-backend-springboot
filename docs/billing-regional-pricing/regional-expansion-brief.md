# 地区差异化定价：简版技术方案

基于前后端 `feat/billing-brazil-pricing` 分支开发。本文只说明本次问题、规则及实现方案，具体金额见[价格配置表](regional-expansion-prices.json)。当前为方案文档，尚未实施。

## 1. 本次做什么

为以下 11 个地区提供固定本币价格，套餐权益不变：

| 定价区 | 国家/地区 | 币种 |
| --- | --- | --- |
| Z025（0.25） | 印尼 | IDR |
| Z030（0.30） | 泰国 | THB |
| Z040（0.40） | 土耳其、巴西 | TRY、BRL |
| Z065（0.65） | 台湾、韩国 | TWD、KRW |
| Z070（0.70） | 意大利 | EUR |
| Z080（0.80） | 香港、德国、奥地利 | HKD、EUR |
| Z085（0.85） | 瑞典 | SEK |

覆盖 Basic、Plus、Pro 月/年付、7 天付费试用、三个会员额外包及 Study Pass。新购 Pro 使用表格的“新 Pro”价格，巴西也使用新表价格。**旧积分包（旧独立额度包）本次不动；适用的已有订阅本期保持原价，下一个付费周期切换新版本，定价区和币种不变。** 其他地区保留原销售规则。

Study Pass 按 USD 0.99 × 地区倍率 × 固定折算参考生成本币月价；低于实际扣款下限时，在配置阶段上调。现有建议价尚需核验目标账户最低扣款，不在付款时动态换汇或加价。

## 2. 当前问题

巴西分支已经能识别地区、选择币种、展示报价并创建支付，但一个 SKU 仍主要对应一个销售 Price。

只按币种选价不够：德国 Basic 是 **€13.99/月**，意大利是 **€11.99/月**，两者都使用 EUR。另外，新增 Price 后，支付回调必须识别它属于哪个套餐；试用转正、续费和套餐变更也不能误用另一地区或新版本的价格。

## 3. 实现方案

**① 复用 Product，按定价区新增 Price。**

每个“定价区＋SKU”配置一条 Stripe Price，同区的不同币种放在该 Price 的 `currency_options` 中。德国与奥地利共用 Z080/EUR，意大利用 Z070/EUR。共 77 条地区 Price、110 个本币金额；统一设置 USD 默认金额，但收费时后端明确指定对应本币。旧 Price 不覆盖。

**② 后端统一选择价格。**

```text
独立新购：可信国家 → 定价区＋币种 → 当前价格版本 → SKU 的 Price ID
已有合同当前操作：原定价区＋当前生效版本＋币种 → 目标 SKU 的 Price ID
发布新价：同区同币种的新版本 → 安排下一付费周期生效
```

新增国家路由、价格版本及 Price 映射配置。复用现有可信地区识别，不接受前端指定 Price 或定价区。Stripe 返回金额与配置核对；已匹配地区但缺 Price/币种时禁止购买，不静默改为美元收费。

**③ 本期保持原价，下个付费周期换新价。**

维护 `Price ID → 定价区、版本、SKU` 映射，复用订单 `biz_context` 保存历史快照。发布新价时，后端先核对受影响合同，再通过 Subscription Schedule 保留当前阶段，在原周期结束点切换到新 Price。不能只更新销售配置；必须逐合同安排并记录结果。沿用现有 Stripe 对象和订单结构，不为价格版本新增数据库表。

月付等下次月续费，年付等下次年度续费，Study Pass 按自己的月付周期。已有试用转正、降级计划必须合并更新，不能覆盖用户安排；已取消续费的不能被重新开启。当前周期额外包和立即变更使用当前生效版本，下一期变更使用已安排目标。价格切换不改历史订单、不产生本期补扣或退款。

例如：归属已核实的巴西 Pro 本期已付 R$399.90，下次续费改为 R$60.99。德国用户去意大利仍属于德国定价区。旧合同若缺少区归属或同币种目标价，列入待核对，不能按当前 IP 猜测，也不能自动把 USD 换成本币。

**④ 接通完整付款流程，保留已有 API。**

| 代码位置 | 改动 |
| --- | --- |
| `BillingRegionalPricingProperties`、`BillingPricingService` | 增加地区、版本和 Price 映射，统一解析实际 Price、金额及币种 |
| `BillingDomainServiceImpl` | 新购、试用转正、升降级、额外包和 Study Pass 都使用解析结果；同时替换 Price ID、金额和币种 |
| `StripeBillingWebhookService` | 通过新旧 Price 映射识别 SKU，沿用原权益发放、幂等及重试逻辑 |
| 新价发布执行入口 | 生成逐合同迁移清单、合并 Schedule、重试并核验生效；旧任务不得覆盖用户变更或更新版本 |
| 前端及 Checkout 文案 | 继续展示后端报价；修正后端韩元固定除以 100 的问题 |

复用现有报价接口和 `quoteVersion`，将区、版本、Price 和试用转正目标纳入报价指纹。即使两地试用首付相同，续费价不同也必须重新确认。Checkout 和 Schedule 明确传入币种。

套餐升降级继续按权益等级判断，保留原收费算法。例如德国 Plus 月付升级到更便宜的新 Pro，按现有月付升级规则收取完整目标月费 €20.99，不计算负差价退款。不新增支付方式选择逻辑。

## 4. 最小验收与上线要求

- 核对全部地区、SKU、币种和金额；重点验证德国/意大利同币种不同价、巴西新旧价及 KRW/TWD/IDR 金额单位。
- 验证月付/年付/Pass 下期换价、试用转正及降级计划合并、取消、失败重试和旅行场景；已出账或归属不明的合同不能强行迁移。Study Pass 必须验证最低扣款及次月续费。
- 先沙盒验收再发布。关闭新购开关不会撤销已安排的换价，撤销未生效安排需单独处理；历史订单和旧积分包不变。

对应规格：[下周期价格切换 spec](specs/subscription-price-rollout/spec.md)。
