2.2 创建支付会话
创建 Stripe Checkout Session，返回支付链接，用户完成支付后由 Webhook 回调完成充值。
接口：POST /v1/payment/create-checkout-session
请求头：
● Content-Type: application/json
● Authorization: Bearer ${clerk_session_token}（按项目配置）
请求体：
{
  "clerkUserId": "user_xxxxxxxx",
  "customerEmail": "user@example.com",
  "packageType": "assignment_5",
  "successUrl": "http://localhost:3000/payment-success?sessionId={CHECKOUT_SESSION_ID}",
  "cancelUrl": "http://localhost:3000/pricing?canceled=true"
}

字段
类型
必填
说明
clerkUserId
string
是
Clerk 用户 ID
customerEmail
string
否
预填邮箱
packageType
string
是
assignment_1 / assignment_5 / assignment_10 / assignment_50 / starter / pro / academic
successUrl
string
否
支付成功跳转 URL，建议带 {CHECKOUT_SESSION_ID}
cancelUrl
string
否
取消支付跳转 URL
成功响应示例：
{
  "meta": {
    "statusCode": 0,
    "statusMsg": "success",
    "traceId": "trace_abc123"
  },
  "data": {
    "sessionId": "cs_test_xxxxxxxxxxxx",
    "checkoutUrl": "https://checkout.stripe.com/c/pay/cs\_test\_xxx",
    "expiresAt": 1772367233
  }
}

前端流程：重定向用户到 checkoutUrl，支付完成后跳回 successUrl，可从 URL 参数获取 sessionId 用于查询状态。
错误示例（无效套餐）：
{
  "meta": {
    "statusCode": 4001,
    "statusMsg": "Invalid package type: xxx",
    "traceId": "trace_xxx"
  },
  "data": null
}

四、cURL 示例
获取余额：
curl -X GET "${NEXT_PUBLIC_API_BASE_URL}/v1/quota/balance" \
  -H "Authorization: Bearer ${CLERK_TOKEN}"

获取交易流水：
curl -X GET "${NEXT_PUBLIC_API_BASE_URL}/v1/quota/ledger?page=1&page_size=20&feature_code=task_create" \
  -H "Authorization: Bearer ${CLERK_TOKEN}"

创建支付会话：
curl -X POST "${NEXT_PUBLIC_API_BASE_URL}/v1/payment/create-checkout-session" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer ${CLERK_TOKEN}" \
  -d '{
    "clerkUserId": "user_xxx",
    "customerEmail": "user@example.com",
    "packageType": "assignment_5",
    "successUrl": "http://localhost:3000/payment-success?sessionId={CHECKOUT_SESSION_ID}",
    "cancelUrl": "http://localhost:3000/pricing?canceled=true"
  }'

整体商业化余额体系
每个用户账户维护三种独立余额：
1. Assignment 次数余额
2. AI Detection 字数余额
3. Humanizer 字数余额
说明：
● 三者完全独立
● 免费额度按月重置
● 购买额度永久有效（不过期）
重置规则
● 每月 1 号 00:00（UTC+0）重置
● 未使用免费额度清零
